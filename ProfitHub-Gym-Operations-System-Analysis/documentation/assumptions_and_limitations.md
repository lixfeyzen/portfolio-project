# Assumptions and Limitations

## Assumptions

- This is a system analysis portfolio case study.
- The gym context is hypothetical and used for documentation practice.
- No real gym client data is used.
- The MVP focuses on internal gym operations.
- Members are represented as data records and class booking participants only.
- Admin staff manually record offline payments.
- Owners need operational summaries, not complex accounting.
- Trainers need assigned class and attendance access only.
- Public feature benchmarking was used to ground MVP scope.

## Limitations

- No full application is built in this project.
- No member mobile app is included in the MVP.
- Payment gateway integration is excluded from the MVP.
- Multi-branch management is excluded from the MVP.
- Trainer payroll is excluded from the MVP.
- Inventory management is excluded from the MVP.
- Advanced CRM and marketing automation are excluded from the MVP.
- Diagrams are conceptual and for planning.
- API specification is draft-level, not production implementation.
- No production deployment is claimed.
- No fake screenshots are included.
- No real interviews have been claimed unless separately conducted.
- No confidential gym data was used.
- Public benchmark sources are used only to support general feature relevance,
  not to copy product design.
