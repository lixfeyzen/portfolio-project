# Non-Functional Requirements

| ID | Category | Requirement |
| --- | --- | --- |
| NFR-001 | Usability | Common workflows should use clear forms and validation messages. |
| NFR-002 | Security | Password values must be hashed and excluded from API responses. |
| NFR-003 | Role-Based Access | Actions must be restricted by assigned user role. |
| NFR-004 | Data Validation | Required fields, dates, amounts, email format, and status values must be checked. |
| NFR-005 | Performance | Search, unpaid lists, and dashboard summaries should respond quickly. |
| NFR-006 | Auditability | Operational records should store created date, updated date, and staff user. |
| NFR-007 | Availability | The system should be available during gym operating hours. |
| NFR-008 | Maintainability | Requirements, API contracts, and data model notes should be clear. |
| NFR-009 | Scalability | Core entities should support future portal, payment, and branch expansion. |
| NFR-010 | Backup and Recovery | Core operational data should be included in scheduled backups. |
| NFR-011 | Privacy | Member contact information should be visible only to authorized staff. |
| NFR-012 | Consistency | Status values should use controlled lists for reliable reporting. |
